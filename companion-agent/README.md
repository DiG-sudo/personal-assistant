## 只划分三块

| 部分 | 核心问题 | 包含内容 |
| --- | --- | --- |
| 人格 | 助手是谁，长期保持怎样的性格与表达习惯？ | 核心设定、表达风格、对话示例、场景适配与人格版本 |
| 记忆 | 助手认识谁，记得什么，怎样延续共同经历？ | 用户信息与偏好、共同经历、相处约定、未完话题、写入与召回、纠正与遗忘、跨会话归属 |
| 行为 | 助手此刻如何回应，什么时候主动联系？ | 回复策略、话题延续、等待与时机、主动联系、打扰控制、可选情绪状态 |

这是业务逻辑划分，不要求建立三个服务、三个新接口或三个独立存储。情绪归行为；关系中的事实、约定和经历归记忆；称呼与亲疏的当下表达归行为。

以下“开发目标”是后续设计方向，不表示已实现或已确定所有参数。

## 与现有骨架的关系

| 现有位置 | 延续的职责 | 三块能力怎样使用它 |
| --- | --- | --- |
| 版本化提示词 / 发布清单 | 固定提示词、组件、工具与配置版本 | 人格及行为规则通过新版本发布，保留旧资源和清单 |
| MemoryModule | 长期记忆召回与维护 | 承载用户资料、经历、约定和未完话题；当前字符串契约的扩展另行设计 |
| ContextBuilder | 每次推理前组织临时模型输入 | 组合已校验人格、选中记忆、相关行为信息和本轮消息；保留工具配对，不改原始历史 |
| ConversationService | 会话串行与 steer | 后续主动事件也遵守会话执行边界；共享记忆的跨会话写入还需自己的并发约束 |
| AssistantHarness | 恢复、生命周期、检查点及提交后的记忆更新 | 保持现有明确边界，不为三块能力另建一套生命周期 |
| AgentRuntime | 模型/工具循环和实际请求预算 | 不加入具体角色、业务工具名或社交定时器；新增模型请求必须可计数 |
| ConversationStore | 权威聊天与恢复检查点 | 提供记忆来源；记忆或检索索引不替代聊天记录 |

人格与固定行为规则属于可信配置；召回内容仍是可能有误的数据，不能取得系统或工具权限。新增工具继续使用 VersionedToolCallback，并由发布清单精确选择。

## 建议的开发顺序

| 顺序 | 涉及部分 | 最小交付目标 | 完成依据 |
| --- | --- | --- | --- |
| 1 | 人格 | 先完成独立类，再确定人设与少量示例，后续接入新提示词版本 | 独立类的版本与指纹可验证；接入后另行验证表现与执行快照 |
| 2 | 记忆 | 先支持明确范围内的保存、召回和纠正，再延伸共同经历 | 不串范围、纠正有效、来源可查；实现中的非平凡规则有小范围可运行检查 |
| 3 | 行为 | 利用人格与记忆改善接话、追问和后续跟进 | 行为有当前输入或历史依据，不重复、不编造 |
| 4 | 行为 | 增加用户可控制的主动联系；情绪状态按实际需要加入 | 安静时段/冷却/发送结果准确，额外模型调用有明确预算 |

正式实现时按项目要求新增行为版本；行为变化同步更新 docs/ARCHITECTURE.md 与 docs/ISSUES.md。设计阶段不改变运行行为；具体实现进展以开发日志为准。
