## 记忆：认识用户与延续经历

| 包含内容 | 当前项目基础 | 开发目标 | 源码参考 |
| --- | --- | --- | --- |
| 用户信息与偏好 | NoteMemory 仅记录以“记住：/记住:”开头的首条用户输入 | 保留称呼、沟通偏好及用户明确提供的稳定信息；区分事实与推测 | R04、R05 |
| 共同经历与相处约定 | ConversationStore 保存原始聊天；暂无经历整理 | 记录重要经历、约定和未完话题，并关联来源轮次；不另存第二份完整聊天 | R06、R14、R15、R16 |
| 写入与维护 | 成功轮次提交后 observe；按来源 turn ID 幂等保存 | 明确哪些信息值得保存；支持纠正、删除和失效；不能只凭模型说“记住了”判断写入成功 | R04、R05、R06 |
| 召回与预算 | 当前返回本会话最新 20 条备注，不使用 query 筛选；上下文另有记忆字符预算 | 少量关键资料常驻；经历按当前话题召回；先判断相关性，再排序和去重，允许没有结果 | R05、R06、R14、R15、R16 |
| 跨会话连续性 | 默认按 conversationId 隔离；尚无用户身份授权 | 明确用户、助手角色、会话及必要的项目范围；同一用户跨窗口延续，其他范围保持隔离 | R03、R05、R15 |

MemoryModule 继续拥有长期记忆；ConversationStore 继续拥有权威聊天。关系信息是记忆的内容类型，先不建立独立“关系系统”或亲密度分数。

## “记忆数据”的确切含义

它表示从长期记忆存储召回、再经 ContextBuilder 预算选择后进入模型输入的数据，不是整个长期记忆库，也不是服务商的 prompt/KV 缓存。

| 对象 | 当前含义 | 是否持久化 |
| --- | --- | --- |
| 长期记忆存储 | NoteMemory 在本地 memory 目录保存的显式备注，带 sourceTurnId 与创建时间 | 是；按 conversationId 隔离，跨重启可保留，不是跨会话个人画像 |
| 本轮召回快照 | MemoryModule.recall 的结果；当前按时间倒序取最新 20 条，未使用 query 做相关性筛选 | 运行期快照；来源条目已持久化，不另存第二份聊天 |
| 模型中的记忆数据块 | Builder 从召回结果中按 memoryChars 预算挑选的备注，默认 4000 字符，以 UserMessage 数据块提供 | 临时模型视图，不改权威历史 |
| 聊天历史 | ConversationStore 中的原始聊天和检查点；Builder 当前只选部分成功历史轮次 | 是；与长期备注存储分开 |
| Prompt/KV 缓存 | 服务商复用相同请求前缀的计算状态 | 不是业务长期记忆，不能作为可靠存储或恢复依据 |

当前 NoteMemory 只检查成功轮次的首条用户消息，要求以“记住：”或“记住:”开头；普通聊天中的偏好不会自动写入。Harness 每轮开始 recall，成功提交后 observe。后续用户资料、共同经历和表达经验属于规划能力，当前实现还只是显式备注。
