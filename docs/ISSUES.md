# 已知边界与后续事项

当前已经跑通聊天、工具调用、文件检查点、可替换组件。以下功能均未假装为现有能力。

| 优先级 | 事项 | 何时实现 |
| --- | --- | --- |
| P1 | 接入真实模型并验证供应商工具协议 | 配置 API Key、模型和端点后进行一次真实调用 |
| P1 | 视频实际检索 | 确定平台或搜索服务后，用结构化结果替换目前的搜索入口工具 |
| P2 | 精确 token 预算 | 字符预算不足以避免上下文超限时 |
| P2 | 本轮工具历史裁剪或摘要 | 连续大工具输出开始频繁触发预算时 |
| P2 | SSE / HTTP 取消入口与同步任务中断 | 同步等待体验不满足日常使用时 |
| P2 | 单会话记录分页与索引 | 文件数量增长、每次扫描的实际耗时明显时 |
| P2 | HTTP 请求幂等键 | 客户端需要自动重试、避免同条输入生成多个轮次时 |
| P3 | 无碰撞会话锁 | 锁条带碰撞出现实际吞吐问题时 |
| P3 | 远程访问身份与授权 | 准备开放本机以外访问时 |
| P3 | 多进程存储与锁 | 确定需要多实例运行后，整体替换存储并设计协调边界 |

当前文件保存使用原子重命名，未承诺断电级持久化。进程中断后的 RUNNING 轮次保留为失败记录，工具不会自动重放。


演示模式用于本地调用链验证。当前默认注册七个内置工具，启动需要工作区与 Shell 镜像配置。

当前没有后台队列、分布式 Worker、插件市场或动态 JAR 热加载。需要这些功能时先说明实际场景，再决定是否扩大骨架。

## 已清理：运行时版本化

启动时使用普通配置装配组件，工具通过 Bean 注册。新对话不保存版本快照，历史格式 1 和 2 仍可读取。历史发布资料见 [版本归档](VERSIONING.md)。

## 已清理：参数、状态与派生计算重复

按 ponytail 与 redundancy-design-audit 核对调用链后，清理 11 处：

- 2 组重复参数：版本工厂重复接收已在 BeanFactory 中的组件；complete 重传最后检查点已有的消息。
- 1 份重复结果状态：已删除 Runtime.Result；本次进一步由 AgentExecution 统一保存调用次数，回答读取已提交记录。
- 2 项重复依赖：Controller 不再同时持有 manifest 与模型/工具执行器来生成相同元信息。
- 1 处手工容器查找：使用 resolveNamedBean 代替遍历 Bean Map 后按对象身份查找。
- 1 处重复派生计算：工具名称在注册时排序，读取列表时不重排。
- 2 组重复字段映射：上下文和预算记录直接转换为 JSON Map。
- 2 个临时可变 Map：组件快照和模型安全参数直接用不可变 Map 构造。

当时保留了模型响应、调用预算、工具允许列表、版本匹配、校验和、恢复记录和持久化失败处理。这些是实际边界，不能因“精简”删除。

## 已实现：明确的 Harness 执行边界

- aroundRun 管恢复与提交，aroundReasoning 在每步构造上下文，aroundModelCall / aroundToolRound 包装真实操作；Runtime 只推进协议和预算。
- AgentExecution 保存唯一的提交游标和请求计数，移除 Runtime 内的可变消息副本与重复计数返回值。诊断数据不写入会话事实。
- 按 turnId/stage 记录召回摘要、上下文选择、实际模型次数和工具调用 ID，复用已有 manifest 与工具结果。
- serial@1.1.0 传播取消异常，serial@1.0.0 和两个旧发布清单保留；默认新增 assistant-harness-1.1.0。
- 保留模型协议、最终请求字符预算、工具允许列表、先保存意图、提交失败停止和会话锁 finally。这些是实际边界。

本次冗余审计清理 3 类共 4 处：一份 Runtime 可变消息副本、一项重复的调用次数返回值、一组检查点全量消息传参，以及 Harness 的数组可变游标。现在当前消息与回答均来自同一成功提交记录；工具执行与错误处理共用既有实现。

仍未实现：诊断日志的专用持久化/查询页、完整模型输入归档、HTTP 取消接口，以及供应商推理元数据/多模态消息持久化。当前文本/工具协议和选择摘要不能保证完整重放。

本次 15 项本地小检查覆盖执行边界与版本保留，不运行复杂测试或外部模型。

## 已简化：主流程可读性

对照 pragent 的写法，清理 3 类共 4 处结构：1 个只有单一实现的协调接口、2 个通用日志回调包装器（stage、diagnostic）、1 处 Harness 对 Runtime 的反向持有。现在 Runtime.chat 将 runLoop 方法引用交给 Harness.aroundRun，Harness 用普通方法完成恢复、上下文、工具和提交。

当时的组件端口可替换，已提交轮次是消息与回答的唯一来源。模型响应检查、预算、工具允许列表、意图先保存、失败停止与锁释放均保留。记录日志直接写在对应方法中，上下文选择诊断独立为简单私有方法。

本次保留全部已发布资源，用 Git 修订和实现指纹区分源码；复用 18 项本地小检查，没有新增复杂测试。会话消息队列、steer 与取消未在本次加入。


## 已实现：阻塞会话层与 steer

- ConversationService 按 conversationId 管理 Session。普通请求使用公平执行锁，各自执行一轮并返回 Reply；等待输入通过 UUID 登记和原子 remove 认领。
- POST /api/chat 接收客户端生成的 messageId；POST /api/steer 只接收会话与输入 ID。客户端可在执行中继续发送，并通过 steer 接口将等待消息转为补充。
- 被提升的原请求返回 202 STEERED，不创建独立轮次、不报告普通执行失败。steer 接口不能认领消息时返回 409。
- Harness 每次推理前提交一条补充，保存成功后移除；保留完整工具配对。Runtime 在无工具调用的结束分支检查补充，继续推理也受原预算限制。
- 每轮独立补充列表，极晚输入不自动进入下一轮。接收语义为尽力处理，不增加原子截止状态机。接收回执不表示模型已应用。
- 新默认发布 session-v1.yml，旧发布清单和提示词保留，增加 ConversationService 指纹。普通聊天通过 Session 调用 Runtime.chat，再由 Runtime 进入 Harness 生命周期；历史查询仍由 Controller 直接调用 Harness，读取已保存检查点，不等待执行锁。会话层不依赖 Harness，没有新增线程池、后台消费者、SSE 或轮询。
- 未实现：取消接口、持久排队、自动重试/幂等、补充的严格接收截止。并发、外部网络和真实模型检查仍为按需入口。

## 已实现：CLI 纯文本流

- DeepSeek V4.1 Flash 的非思考模式可通过 YAML 配置 assistant.model.reasoning-effort=none 使用工具。当前对话记录不回传 thinking 模式要求的 reasoning_content。

- POST /api/chat/stream 通过当前请求的回调输出 turn 起止、实际模型请求序号、每批工具的名称与参数、结果摘要、成功数、失败数和耗时。执行失败时复用原有失败原因。已保存的补充消息发内部 TurnSteer，CLI 不单独显示。
- 失败统计识别默认执行器的两种错误前缀。自定义工具或执行器若用普通文本表示失败，目前没有独立状态可供统计。
- 进度输出使用同一请求线程。断开连接不取消正在执行的 turn，当前不提供事件重连或回放。

## 已迁移：工具注册与分批执行

参考 PR Review Agent 的工具注册表、单次执行与分批调度。连续 READ 并行，WRITE 和 SHELL 在轮内单独执行。工具结果仍按模型调用顺序提交，HTTP 工具统计使用执行结果的成功状态。

## 已统一：工具装配入口

内置工具与自定义工具统一声明为 `ToolBinding` Bean。`BuiltinToolConfiguration` 明确声明每项内置工具的执行类型，默认注册表收集全部工具 Bean。名称唯一性由 `ToolRegistry` 检查。

已删除工具名配置、条件注解、启用筛选及缺失名称检查。自定义工具与内置工具同名时统一报错。默认装配在启动时初始化全部内置工具并检查工作区与镜像名。完整自定义注册表决定自己的工具范围，内置组件按依赖延迟创建。路径、工作区分离、镜像、执行类型与未知工具调用的检查继续由各自边界负责。

## 已接入：工作区文件工具与 Shell

文件工具与 Shell 沿用 AgentScope Java 的工具名称和参数，通过 `ToolBinding` Bean 统一注册。文件操作基于一个操作者配置的工作区。当前路径检查假定宿主机上的其他程序不会在操作期间恶意替换工作区目录，工作区内已有硬链接的文件内容可被读取。

Shell 使用临时副本，限制为 128 MiB 和 20,000 个目录项，构建依赖需要已在镜像或工作区内。容器和临时目录的清理在正常返回、超时和取消时执行，进程被强制终止可能留下临时文件。Docker 守护进程可用后仍需做真实容器冒烟检查。
