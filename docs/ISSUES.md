# 已知边界与后续事项

当前已经跑通聊天、工具调用、文件检查点、可替换组件和显式备注记忆。以下功能均未假装为现有能力。

| 优先级 | 事项 | 何时实现 |
| --- | --- | --- |
| P1 | 接入真实模型并验证供应商工具协议 | 配置 API Key、模型和端点后进行一次真实调用 |
| P1 | 视频实际检索 | 确定平台或搜索服务后，用结构化结果替换目前的搜索入口工具 |
| P1 | 长期记忆可靠补偿 | 需要保证回答保存后每条显式备注最终都入库时，按来源 turn ID 补偿 |
| P2 | 记忆删除、修改与迁移入口 | 开始长期使用显式备注时；当前通过本地 JSON 文件管理 |
| P2 | 精确 token 预算 | 字符预算不足以避免上下文超限时 |
| P2 | 本轮工具历史裁剪或摘要 | 连续大工具输出开始频繁触发预算时 |
| P2 | SSE / 取消执行 | 同步等待体验不满足日常使用时 |
| P2 | 单会话记录分页与索引 | 文件数量增长、每次扫描的实际耗时明显时 |
| P2 | HTTP 请求幂等键 | 客户端需要自动重试、避免同条输入生成多个轮次时 |
| P3 | 无碰撞会话锁 | 锁条带碰撞出现实际吞吐问题时 |
| P3 | 远程访问身份与授权 | 准备开放本机以外访问时 |
| P3 | 多进程存储与锁 | 确定需要多实例运行后，整体替换存储并设计协调边界 |

当前文件保存使用原子重命名，未承诺断电级持久化。进程中断后的 RUNNING 轮次保留为失败记录，工具不会自动重放。

默认 NoteMemory 为 conversationId 范围，不是跨对话个人画像。替换实现前确认记忆范围、持久化格式与旧数据迁移路线。

演示模式不是大模型能力评估。默认视频工具只生成公共搜索入口，不检索、验证、下载资源。

当前没有后台队列、分布式 Worker、插件市场或动态 JAR 热加载。需要这些功能时先说明实际场景，再决定是否扩大骨架。

## 已实现：版本管理

发布组合使用独立清单，提示词有版本路径与 SHA-256，组件有版本声明与实现指纹，工具按明确版本选择。新聊天保存不可变版本快照；旧记录保留无版本状态。自定义参数通过 ConfigurationSnapshot 提供。

当前提供配置级手动对比和回退路线，未新增自动评测平台。模型供应商数据、外部工具结果和记忆变化仍可能影响回答。跨版本数据格式迁移需由对应组件明确实现，不能仅靠切回清单自动完成。
